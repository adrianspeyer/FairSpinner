Provably fair, in plain terms

FairSpin uses a commit–reveal scheme. The wheel is just the show: the winner is computed from cryptographic hashes that anyone can recompute later, with this file or a few lines of Python.

The flow

  1. Lock. The list is frozen and fingerprinted: SHA-256 of the entries joined by newlines (UTF-8). A 256-bit secret seed is generated with the browser's cryptographic RNG (crypto.getRandomValues). Only its hash — the seed commitment — is shown.
  2. Publish. You post the list hash + seed commitment publicly before spinning. Now the list can't be edited and the seed can't be swapped without the hashes changing.
  3. Public entropy (optional). Announce a future public value (e.g. "the hash of Bitcoin block #N") in the same post. Once it exists, paste it in. Because it didn't exist when you committed to the seed, you couldn't have tried seeds until one favoured someone.
  4. Draw. For draw n: HMAC-SHA256(key = seed, msg = "fairspin/v1|list:<listHash>|entropy:<entropy>|draw:<n>|ctr:<c>"). The first 4 bytes become an unsigned 32-bit number r. If r ≥ ⌊2³²/N⌋·N it's rejected and c goes up by 1, which avoids modulo bias. Otherwise the winner is pool[r mod N].
  5. Pool. The original list order, minus previous winners if "winners leave the pool" was on at lock time.
  6. Reveal. The audit JSON includes the seed, every input, every draw and a timestamped event log. Anyone can check that SHA-256(seed) matches the commitment you posted, then recompute each winner.

What the recordings prove

The GIF and certificate show the timestamp, the draw number and the hash fingerprints. The wheel always lands on the slice the math picked: the animation is driven by the result, not the other way round. On its own the GIF is presentation. The proof is the hashes.

Honest limits

The person running the draw holds the seed. Without public entropy, an organiser could in theory generate seeds privately until one favoured a friend, and only then publish the commitment. Public entropy from a future event closes that gap. Posting the commitment before the entropy exists is what makes it airtight.

Independent check (Python 3, standard library only)

import hmac, hashlib, json, sys
a = json.load(open(sys.argv[1], encoding="utf-8"))
H = lambda b: hashlib.sha256(b).hexdigest()
E = a["list"]["entries"]
lh = H("\n".join(E).encode()); assert lh == a["list"]["sha256"], "list hash mismatch"
seed = bytes.fromhex(a["reveal"]["seed"])
assert H(seed) == a["commitment"]["seedSha256"], "seed does not match commitment"
ent, taken = a["entropy"]["value"], []
for d in a["draws"]:
    pool = [i for i in range(len(E)) if not (a["commitment"]["removeWinners"] and i in taken)]
    N = len(pool); lim = (2**32 // N) * N; c = 0
    while True:
        m = f"fairspin/v1|list:{lh}|entropy:{ent}|draw:{d['n']}|ctr:{c}".encode()
        r = int.from_bytes(hmac.new(seed, m, hashlib.sha256).digest()[:4], "big")
        if r < lim: break
        c += 1
    w = pool[r % N]
    assert E[w] == d["winner"], f"draw {d['n']} mismatch"
    taken.append(w); print(f"draw {d['n']}: OK -> {E[w]}")
